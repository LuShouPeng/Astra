# 项目状态记录体系

跟踪「真实 Agent 集成」开发进度，对齐 [`../real-agent-integration.md`](../real-agent-integration.md) 的里程碑。

## 文件

| 文件 | 作用 | 更新方式 |
|------|------|---------|
| [`STATUS.md`](./STATUS.md) | **当前状态**，唯一事实源 | 每个里程碑**覆盖更新** |
| [`history/`](./history/) | **历史快照**，逐里程碑冻结 | 只新增，**永不修改** |

## 每完成一个里程碑的更新流程

1. **真机验证**（涉及真实 CLI / 进程 / IPC 行为时必做）：单测与 mock 只能证明逻辑正确，
   证明不了端到端真机行为。凡里程碑触及真实 CLI、子进程、Tauri IPC，必须在本机实测一次
   （临时测试 + `--nocapture`，或 `npm run tauri dev` 端到端），并把真实输出记进快照。
   临时测试看完即删，不进回归套件（它依赖本机环境）。声明"X 会发生"前先实测，
   否则措辞为"设计如此，未经真机验证"。
2. 把 `STATUS.md` 的当前内容**复制**到 `history/M{n}-{slug}.md`，在顶部标注该里程碑完成日期与 commit/tag，此后冻结不再改。
3. 更新 `STATUS.md`：里程碑总览、六项能力状态、已实现/需修改/未开发三张表、契约现状，改到反映最新真实状态。
4. 更新顶部元信息（日期、当前里程碑、最新 commit、测试计数、真机验证结果）。
5. 随里程碑代码一起提交，commit message 带上状态更新。

## 图例

- ✅ 已实现：功能完整、连到真实后端、可用
- 🔧 需修改：已存在但为 mock/占位，须改造
- ❌ 未开发：目标功能，代码中完全不存在

## 原则

- **代码验证优先**：状态判断必须基于实际读代码，不凭记忆或计划推断。
- **真机优先于 mock**：涉及真实 CLI/进程/IPC 的功能，单测通过 ≠ 真机可用。声明真机行为前先实测。
- **区分"装没装"与"能不能用"**：探测/存在性检查证明的是可执行文件存在，不代表已授权、可实际运行。
- **历史不可变**：`history/` 里的快照是某一时点的真相，后续里程碑不回改，便于对比演进。
